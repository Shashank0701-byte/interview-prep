# GitOps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement a complete GitOps pipeline: security audits on PRs, Dependabot for automated dependency updates, CD to Render on merge, branch protection enforced via GitHub, and GitHub Environments for secret management.

**Architecture:** All automation lives in `.github/` — a new `security.yml` workflow adds audit + secret-leak detection, a `deploy.yml` workflow triggers Render's deploy hook after CI passes on `main`, and `dependabot.yml` automates dependency PRs. Branch protection rules are set via the `gh` CLI and GitHub Environments replace the plaintext `.env` files on the server.

**Tech Stack:** GitHub Actions, `gh` CLI, Render deploy hooks, Netlify (already auto-deploys), Dependabot, `npm audit`, `trufflehog` OSS for secret scanning.

## Global Constraints

- Node.js >= 18, use 22 in all Actions (matches existing `ci.yml`)
- Python 3.12 (matches existing `ci.yml`)
- All new workflow files use `actions/checkout@v4`, `actions/setup-node@v4`
- Do NOT modify `ci.yml` — extend the pipeline with new workflow files only
- All secrets referenced in workflows must be added to GitHub repo settings before the workflow runs
- Render deploy hook URL stored as `RENDER_DEPLOY_HOOK_URL` secret in the `production` GitHub Environment
- Frontend already deploys from `main` via Netlify — no change needed there

## Task 1: Security Audit Workflow

**Files:**
- Create: `.github/workflows/security.yml`

**Interfaces:**
- Produces: `security` GitHub Actions workflow with two jobs: `audit` (npm audit both packages) and `secret-scan` (trufflehog on diff)
- Later tasks depend on nothing from this task

- [ ] **Step 1: Create the workflow file**

Create `.github/workflows/security.yml` with this exact content:

```yaml
name: Security — Audit & Secret Scan

on:
  push:
    branches: [main, dev, feat/**]
  pull_request:
    branches: [main, dev]

jobs:
  # ── npm audit ──────────────────────────────────────────────
  audit:
    name: npm audit
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js 22
        uses: actions/setup-node@v4
        with:
          node-version: 22

      - name: Audit backend
        working-directory: backend
        run: |
          npm install --ignore-scripts
          npm audit --audit-level=high

      - name: Audit frontend
        working-directory: frontend/interview-perp-ai
        run: |
          npm install --ignore-scripts
          npm audit --audit-level=high

  # ── Secret / credential leak scan ─────────────────────────
  secret-scan:
    name: Secret scan (trufflehog)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0   # full history needed for diff scanning

      - name: Run TruffleHog on git diff
        uses: trufflesecurity/trufflehog@main
        with:
          path: ./
          base: ${{ github.event.repository.default_branch }}
          head: HEAD
          extra_args: --only-verified
```

## Task 3: CD Workflow — Deploy to Render on Merge

**Files:**
- Create: `.github/workflows/deploy.yml`

**Interfaces:**
- Consumes: `RENDER_DEPLOY_HOOK_URL` secret from the `production` GitHub Environment
- Produces: automatic Render redeploy triggered after all CI jobs pass on `main`

**Before starting:** You need the Render deploy hook URL.
1. Open Render dashboard → your backend service → Settings → Deploy Hook → copy the URL
2. In GitHub repo → Settings → Environments → New environment → name it `production`
3. Under `production` environment → Add secret → Name: `RENDER_DEPLOY_HOOK_URL` → Value: the URL you copied

- [ ] **Step 1: Add the Render deploy hook secret to GitHub**

Run this to verify the environment exists after you've created it manually in GitHub settings:

```bash
gh api repos/Shashank0701-byte/interview-prep/environments/production --jq '.name'
```

Expected output: `production`

- [ ] **Step 2: Create the deploy workflow**

Create `.github/workflows/deploy.yml` with this exact content:

```yaml
name: CD — Deploy to Production

on:
  push:
    branches: [main]

jobs:
  # Wait for CI to pass first — this re-runs the status check
  # by requiring the same jobs ci.yml runs on PRs.
  # Since this triggers on push to main (after merge), CI already passed;
  # this is a safety gate in case someone pushes directly to main.
  deploy-backend:
    name: Deploy Backend to Render
    runs-on: ubuntu-latest
    environment: production       # requires production environment approval if configured

    steps:
      - name: Trigger Render deploy hook
        run: |
          response=$(curl -s -o /dev/null -w "%{http_code}" \
            -X POST "${{ secrets.RENDER_DEPLOY_HOOK_URL }}")
          echo "Render response: $response"
          if [ "$response" != "200" ] && [ "$response" != "201" ]; then
            echo "Deploy hook failed with status $response"
            exit 1
          fi
          echo "Render deploy triggered successfully"

      - name: Wait and verify deploy started
        run: |
          echo "Deploy triggered. Monitor at https://dashboard.render.com"
          echo "Backend will be live at ${{ vars.RENDER_SERVICE_URL }} once deploy completes."
```

- [ ] **Step 3: Add the optional `RENDER_SERVICE_URL` variable**

In GitHub repo → Settings → Environments → `production` → Environment variables (not secrets) → Add:
- Name: `RENDER_SERVICE_URL`
- Value: `https://interview-prep-1-ferg.onrender.com`

This is non-sensitive so it goes in variables, not secrets.

## Task 5: Secret Leak Prevention — `.env` Push Guard

**Files:**
- Create: `.github/workflows/security.yml` — **add a job to the file created in Task 1**

This extends Task 1's `security.yml` with a job that blocks any push containing an accidentally staged `.env` file.

**Interfaces:**
- Modifies: `.github/workflows/security.yml` (adds `env-file-check` job)

- [ ] **Step 1: Add the env-file-check job to `security.yml`**

Open `.github/workflows/security.yml` and append this job under `jobs:`:

```yaml
  # ── Block accidental .env commits ─────────────────────────
  env-file-check:
    name: Check for committed .env files
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Fail if .env files are tracked
        run: |
          # Check if any .env file (not .env.example) is tracked by git
          if git ls-files | grep -E '(^|/)\.env$'; then
            echo "ERROR: .env file(s) are tracked by git. Remove them and add to .gitignore."
            exit 1
          fi
          echo "No .env files tracked. Safe to proceed."
```
